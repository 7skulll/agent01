## 未实施

以下是仍需完成的工作，按当前证据排序：

1. **审核流程仍需完善**。2026-10-27 的 CRUD 本地记录已有 60 道题的代审结果，
   54 通过、3 部分通过、3 不通过；这是依据实际回答、上下文和原文进行的 Codex 代审，
   不等于业务人员签收。审核人、时间与方法字段已落地（`reviewer` / `reviewed_at` /
   `review_method` / `carried_from`），代审记录标记为 `ai_proxy`，登录员工在工作台保存为 `human`；
   但待审核队列导航与审核表批量导入导出仍缺失。
   数据范围和复用结果说明见 [测评集清单](evaluation-case-sets.md)。
2. **回归门禁未接入 CI**。`GET /evaluations/gate` 已可用，但仓库没有任何 CI 配置，
   门禁只能人工在页面触发。
3. **实验对比口径待统一**。汇总和报告保留生成失败题的实际检索得分，
   `app/evaluation_comparison.py` 仍将失败题的检索得分计零，对比和回归门禁可能因此误报退化。
   修复前应核对逐题状态和检索结果，详见 [指标口径](evaluation-metrics.md)。
4. **多人审核与一致性度量**。当前一题只有一个 `review`，无法做双人标注和分歧率。
5. **结构恢复与父子检索**。当前只按已有标题、页码、连续 `chunk_index` 合并，不能可靠恢复跨页章节。
   需要引入稳定的 `section_id` / `parent_id` 与原文位置映射：子块用于召回、按预算回查父块，
   并保持最终输入、来源快照与可引用集合一致；表格保留表头和完整行，代码和列表保留完整结构；
   解析/切片元数据需版本化并设计迁移。验收覆盖跨页前提/例外、同名标题、长流程、表格、
   预算不足、历史隔离及重启恢复。
6. **并发与部署能力**。当前单进程单 worker，评测同样串行（同一时间只允许一个实验）；
   多进程执行和持久化监控仍需按实际负载设计。

OCR、图片处理和表格数值计算不在当前范围。

## 文档整理原则

- 只保留描述**当前行为**的文档。被取代的历史文档在内容合并后删除，原文可从 git 历史恢复。
- 版本标识、配置默认值、测试数量这类易漂移的事实，写明可在代码中核对的位置，而不是抄数字。
- 历史验证记录中的测试数量都是对应版本的快照，不代表当前版本；本目录不再保留这类流水账，
  需要时查 `git log` 与 `evals/results/`。
