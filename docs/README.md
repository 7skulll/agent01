## 未实施

以下是仍需完成的工作，按当前证据排序：

1. **人工审核闭环尚未跑起来**。审核模型、API 和界面都已实现，但已存结果的
   `verdict` 全部为 `pending`。生成层四指标和回归门禁的回答质量检查因此始终为「未评分」。
   缺少的能力：审核人身份与时间记录、待审核队列导航、审核表导入导出。
2. **回归门禁未接入 CI**。`GET /evaluations/gate` 已可用，但仓库没有任何 CI 配置，
   门禁只能人工在页面触发。
3. **多人审核与一致性度量**。当前一题只有一个 `review`，无法做双人标注和分歧率。
4. **结构恢复与父子检索**。当前只按已有标题、页码、连续 `chunk_index` 合并，不能可靠恢复跨页章节。
   需要引入稳定的 `section_id` / `parent_id` 与原文位置映射：子块用于召回、按预算回查父块，
   并保持最终输入、来源快照与可引用集合一致；表格保留表头和完整行，代码和列表保留完整结构；
   解析/切片元数据需版本化并设计迁移。验收覆盖跨页前提/例外、同名标题、长流程、表格、
   预算不足、历史隔离及重启恢复。
5. **并发与部署能力**。当前单进程单 worker，评测同样串行（同一时间只允许一个实验）；
   多进程执行和持久化监控仍需按实际负载设计。

OCR、图片处理和表格数值计算不在当前范围。

## 文档整理原则

- 只保留描述**当前行为**的文档。被取代的历史文档在内容合并后删除，原文可从 git 历史恢复。
- 版本标识、配置默认值、测试数量这类易漂移的事实，写明可在代码中核对的位置，而不是抄数字。
- 历史验证记录中的测试数量都是对应版本的快照，不代表当前版本；本目录不再保留这类流水账，
  需要时查 `git log` 与 `evals/results/`。
