## 业务质量评估

第一版工程已实现于现有检索调试页面，见 [evaluation-v1.md](evaluation-v1.md)。
可观察真实检索/RAG、标注文件级指标并人工审核；业务资料和固定标注集仍需逐步建立。
第二版工程规划见 [evaluation-v2-plan.md](evaluation-v2-plan.md)。

建立 30–50 条固定业务问答，逐步扩充到 100 条。标注预期答案、必要证据、应拒答原因，
覆盖追问、切库、跨片段条件、否定与例外、表格、冲突、无答案与跨页文档。
现有合成检索集、固定候选重排审计和真实模型冒烟不能替代业务质量评估。

分别衡量：

- 召回 Recall@k / MRR，必要证据进入最终上下文的比例。
- 引用编号正确率、答案事实支持率和必要事实覆盖率。
- 应拒答命中率、误拒答率；区分无命中、装不下、缺事实和冲突。
- 输入 Token、实际模型调用次数及端到端延迟。

采用固定数据和配置配对比较：当前基线、Rerank 开关、不同资料预算。
使用独立验证集校准 Rerank 相关性阈值，避免以非空候选或合法引用宣称回答可靠。
独立语义 verifier 尚未实现，应根据人工评估发现的错误及额外成本决定是否增加。

## 第三版：结构恢复与父子检索（未实施）

当前只按已有标题、页码、连续 chunk_index 合并，不能可靠恢复跨页章节。
需要在解析/切片中引入稳定 section_id / parent_id、父块和原文位置映射：

1. 明确章节、父子块与跨页连续关系，无法证明连续时保持分块。
2. 子块用于召回，按预算回查父块；保持最终输入、来源快照与可引用集合一致。
3. 对表格保留表头和完整行；对代码和列表保留完整结构。
4. 版本化解析/切片元数据并设计迁移；是否重新向量化由实际 Embedding 输入变化决定。
5. 保持检索和组装的独立检查点，暂停、恢复和失败重试复用已保存快照。

实施验收覆盖跨页前提/例外、多章节同名标题、长流程、表格、预算不足、历史隔离及重启恢复。
以业务评估证据决定优先级，不预先承诺准确率提升。
