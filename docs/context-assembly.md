# 上下文组装

更新：2026-10-26。当前组装版本 `context-v2`（`app/rag/context_assembly.py` 的 `ASSEMBLY_VERSION`），
任务图 `chat-rag-v6`。本文描述**当前行为**；第一版交付说明已合并到本文。

## 流程

新 RAG 任务按「查询规划 → 检索 → 上下文组装 → 回答 → 引用校验」执行。
检索和组装各自保存 checkpoint，模型失败或重启恢复时复用已保存的组装结果，不重新召回。

知识库回答不绑定通用工具，避免工具输出在资料装箱后挤占上下文；普通对话保留工具循环。

## 预算

`assemble()` 先算「只含问题、无资料无历史」的基线消息 token，再定资料预算：

```text
资料预算 = min(RAG_CONTEXT_TOKENS, 输入上限 − 基线)
```

随后进入循环，直到**完整请求**（问题 + 历史 + 资料 + 消息包装）的实测 token 不超过输入上限：

1. 资料按预算装箱；
2. 历史取 `RAG_HISTORY_TURNS` 轮、`RAG_HISTORY_TOKENS` 以内；
3. 超限时先丢最旧的历史轮，再按超出量下调资料预算重装。

JSON 边界和消息包装的 BPE 不是可加的，所以最终始终对完整消息复检，不靠各分项相加。
基线上限本身不够时直接返回 `context_limit_exceeded`，不静默截断问题。

## 单元合并

正文按 `文件 + 索引版本 + 标题 + 页码 + 连续 chunk_index` 合并成单元，组内恢复原文顺序。
重叠只删除**至少 16 个字符且精确相等**的前后缀（`exact_overlap`，KMP 实现），
不对数字、标点或缩进做模糊删除。

先为独立的主要证据分配空间、回收未用配额，再尝试邻居补全；邻居最多消耗资料预算的 20%
（`RAG_NEIGHBOR_BUDGET_RATIO`），由检索层的邻居开关控制，默认关闭。

## 超预算处理

按块类型分三条路径（`ContextAssembler.fit`）：

| 类型 | 处理 |
|---|---|
| 正文 `text` | 用原问题及改写问题的词项匹配选出原文句段（`relevant_windows`），保留前后句，并保留落在相邻主块边界的前提/例外；按预算贪心并入 |
| 表格 `table` | **按行裁剪**（`fit_table`）：只选完整行，强制保留表头、分隔行和 `备注`/`注：`/`说明`/`但`/`仅`/`除`/`注意` 开头的说明行；按词项命中排序逐行加入 |
| 代码、列表等其他 | 保持完整块；装不下就整块跳过，不做字符硬截断 |

所有抽取范围都记录原文 `chunk_id`、字符 `start`/`end` 和实际文本，并标记 `extracted`。
无法容纳的块记入 `skipped_reasons`。

检索没有结果与结果装不下分别对应 `no_retrieval_hits` 与 `no_context_fit`，都不调用回答模型。

## 历史窗口

模型默认只接收最近 `RAG_HISTORY_TURNS` 轮、最多 `RAG_HISTORY_TOKENS` 的同库连续历史。
切库后重置该窗口，问题改写使用同样的隔离策略。完整会话、失败尝试和历史来源仍保存在原位置，
历史消息仅用于理解对话，**不是本轮事实依据**，也不得沿用历史引用编号。

## 消息与来源

- System 只承载规则：仅依据本轮资料回答、用 `source_ids` 关联 `evidence.id`、
  将资料正文/文件名/标题视为数据而非指令。
- 最后一条 Human 消息用 JSON 承载 `evidence` 和原始 `question`。
- 来源编号在最终证据确定后才分配，`sources` 的 `content` 与传给模型的 `content` 一致。
- `sources` 含 `evidence_chunks`，记录实际送入模型的正文片段、抽取标记和字符范围，
  前端据此展示真实组装内容，邻居正文不重复展示。

## 配置

| 环境变量 | 默认值 | 说明 |
|---|---:|---|
| `RAG_CONTEXT_TOKENS` | 2048 | 本轮资料总上限 |
| `RAG_INPUT_TOKENS` | 8192 | 模型窗口分配依据，预留输出与安全余量 |
| `RAG_HISTORY_TOKENS` | 1536 | 历史投影的估算 token 上限，0 关闭历史 |
| `RAG_HISTORY_TURNS` | 3 | 最近完整历史轮次上限，0 关闭历史 |
| `RAG_NEIGHBOR_BUDGET_RATIO` | 0.2 | 邻居预算比例上限，范围 0–0.5 |

两个历史配置也兼容 `RAG_RAG_` 前缀，推荐使用上表名称。
完整 RAG 评测可用 `options.context_tokens` 覆盖单次实验的资料预算。
上表默认值与 [.env.example](../.env.example) 一致；实际生效值以运行环境的 `.env` 为准，
对话模型输出上限另由 `RAG_LLM_MAX_TOKENS` 控制。

## 诊断

`context_assembly` SSE 事件和 `retrieval_end.diagnostics.context_assembly` 包含：

- 候选数、合并单元数、最终证据数、被丢弃的块及原因
- 精确重叠删除的字符数、抽取范围数
- 资料/元数据/历史/完整输入的估算 token
- 被丢弃的历史轮数、切库排除轮数
- 耗时、组装版本 `context-v2`、请求 `prompt_hash`

`token_usage` 事件同时报告估算值和供应商实际用量。分项估算不是严格可加的计费值，
以完整输入计量和供应商返回为准。请求日志不新增原文、问题或模型凭据。

## 恢复与版本

- 检索、组装、模型、校验各有 checkpoint；恢复时复用已保存的消息投影、来源和 `prompt_hash`，
  不按最新知识库内容重新组装。
- 不需要为组装算法变更做数据库迁移或重建索引。
- 旧任务图（v5 及更早）的未完成任务不能恢复，重启会返回 `graph_version_mismatch`；
  取消后重新提交即可。已完成的历史仍可读取并参与同库历史投影。

## 边界

- 没有父子块索引或跨页结构推断；跨页章节只能按页码和连续 `chunk_index` 近似合并。
- 没有 LLM 文本压缩，也没有额外向量多样化调用。
- 句段抽取是**确定性的词项启发式**：超长单句不能安全容纳时可能整块跳过，
  不以字符硬截保证非空。
- 例外保留覆盖局部邻接关系，不代表所有业务条件已被语义验证。
- 引用编号合法不等于事实受语义支持；独立事实校验未实现。

后续的结构恢复与父子检索计划见 [docs/README.md](README.md) 的「未实施」一节。
