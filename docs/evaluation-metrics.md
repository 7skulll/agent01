# RAG 评测指标口径

更新：2026-10-23。

本页说明评测页展示的六项核心指标。所有数值都在读取时从已保存的原始数据计算，
不会为了得到更好看的结果而修改、补零或覆盖原始记录。

## 分层评测

评测分为两层，避免把“检索没找到”和“模型答错”混成一个分数：

| 层 | 指标 | 回答的问题 | 数据来源 |
| --- | --- | --- | --- |
| 检索层 | Recall、Precision、MRR | 该找的资料有没有被召回、排得靠不靠前 | 返回来源 + 文件标注 |
| 生成层 | Faithfulness、Answer Relevancy、Answer Correctness、Completeness | 回答是否忠实于上下文、是否答非所问、是否正确、是否完整 | RAGAS 或人工审核 |

页面会同时展示两层的数值和分层诊断提示。诊断阈值只用于定位问题：检索召回低且生成正确性高，优先查切分和召回；召回高但忠实度或正确性低，优先查上下文裁剪、提示词和生成协议。

## RAGAS LLM-as-judge

RAGAS 运行在独立 worker 环境中，主服务不安装 ragas、pandas、datasets 或 pyarrow。未安装 worker 时系统仍可使用人工审核：

```bash
cd tools/ragas-worker
uv sync
```

主服务默认调用 `tools/ragas-worker/.venv/bin/python worker.py`；可用 `RAG_RAGAS_WORKER_COMMAND` 指向独立容器或虚拟环境。

启用后，在完整 RAG 的“受控实验参数”中选择 `RAGAS LLM-as-judge`。评测完成后会为每道完成的回答追加：

- `faithfulness`：回答是否由检索上下文支持。
- `answer_relevancy`：回答是否直接回应问题。
- `answer_correctness`：结合参考答案判断事实正确性；没有参考答案时留空。
- `completeness`：回答是否覆盖参考答案中的必要事实。

RAGAS 分数与人工审核分开保存，缺失分数不补零，也不会覆盖原始回答、检索结果或人工记录。RAGAS 调用会产生额外模型费用，因此默认关闭。

TruLens、DeepEval 更适合后续接入链路追踪和 CI 门禁；本项目当前先把 RAGAS 语义评分和自身回归门禁做好，不引入 BLEU/ROUGE 这类字面匹配指标替代语义判断。

## 评测闭环

1. **造测试集**：在测评集库中导入或保存案例，标注相关文件、参考答案和必要事实。
2. **基线跑分**：用固定配置运行检索或完整 RAG，保存为基线实验。
3. **单一变量对照**：同题对比只改一个参数，例如重排开关、上下文预算或检索方式。
4. **自动化回归**：使用“回归门禁”检查候选实验相对基线的 Recall、MRR 和回答质量下降是否超过阈值。
5. **沉淀 bad case**：把失败、部分正确或 RAGAS 低分题保存为新的草稿测评集，加入下一轮回归。
6. **线上持续监控**：线上反馈和 bad case 需要单独接入反馈接口、日志和定期回归任务；当前页面提供的是离线评测闭环，不把一次跑分当作生产结论。

## 数据来源

- 检索指标直接来自每题的 `sources`（返回来源）与案例的 `relevant_file_ids` 标注。
- 回答质量指标直接来自每题的 `review`（人工审核）字段。
- 未审核、不适用、取消、未执行和服务失败不会自动变成通过。
- `failed` 的完整标注题在检索均值中按零分计入；取消和未执行题不计入。

## 检索指标

排名单位是**返回片段中首次出现的文件去重顺序**，只取前 K 个文件。

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| 精准率 Precision@K | 命中相关文件数 / K | 分母固定为 K，返回不足时按空位补足 |
| 召回率 Recall@K | 命中相关文件数 / 标注相关文件总数 | 只统计完整标注的有答案题 |
| MRR@K | 1 / 第一个相关文件的排名；未命中为 0 | 衡量第一个正确结果出现得多早 |

只有 `expected=answerable` 且 `judgment_scope=full` 的题进入均值。
`partial`、`unlabelled`、`unanswerable` 和未执行题不参与检索质量均值。
文件中命中不等于答案正确，也不等于必要事实已经进入上下文。

## 回答质量指标

三项指标都是严格的二值判定。分母只包含已明确审核为对应枚举值的**已完成且有回答**的题。

| 指标 | 判定 | 原始字段 |
| --- | --- | --- |
| 忠实度 Faithfulness | 回答不存在无资料支持的表述 | `unsupported_claims=no` |
| 正确性 Correctness | 人工总评为通过 | `verdict=pass` |
| 完整性 Completeness | 必要事实完整覆盖 | `fact_coverage=full` |

严格口径：

- `verdict=partial` 不计为正确；页面另外展示“含部分正确的可接受率”，但不替换严格正确性。
- `fact_coverage=partial` 不计为完整。
- `unsupported_claims=yes` 计为不忠实。
- `pending`、`na`、缺失字段和失败题不进入分母；分母为 0 时显示“未评分”，不显示 0%。
- 人工总评、事实覆盖、引用支持和拒答判断仍保留为独立维度，不合并成难以解释的加权总分。

## 测评集库与导入

评测页顶部会显式列出测评集，包括名称、版本、开发/验收用途、审核状态、冻结状态、案例数、
语料文件数、标签和创建时间。可在“当前知识库”和“全部知识库”之间切换；历史创建的
CRUD-RAG 测评集会显示所属知识库。从其他知识库载入时，系统会先切换当前知识库再载入或运行。

- **查看**：读取完整案例，预览问题、预期、标注范围、相关文件数、必要证据数和标签。
- **载入**：把案例装入当前实验配置，修改后会解除与已保存版本的绑定。
- **载入并测试**：载入后立即使用当前“运行方式 / 检索方式 / K / 受控实验参数”运行。
  完整 RAG 会产生真实模型调用。
- **导入测评集 JSON**：保存为新版本，并校验案例中的 `relevant_file_ids` 是否属于当前知识库。

导入格式支持两种：

1. 案例数组：`[{ "query": ..., "expected": ... }]`。
2. 带元数据的对象：

```json
{
  "name": "年假验收集",
  "tags": ["人事", "验收"],
  "split": "acceptance",
  "review_status": "draft",
  "frozen": false,
  "cases": [
    {
      "query": "员工年假多少天？",
      "expected": "answerable",
      "relevant_file_ids": ["当前知识库中的文件 ID"],
      "judgment_scope": "full"
    }
  ]
}
```

文件 ID 必须是当前知识库中已上传的文件；跨知识库导入需要先重新上传资料并映射文件 ID。
冻结版本仍要求人工核验、完整标注和可定位的必要原文，不能通过导入绕过。

## 对比实验

回答质量差值只比较 A、B 两次实验**同一道题在两边都已被明确审核**的情况。
只在一侧审核的题计入“未配对”，不参与差值均值，避免不同审核覆盖度造成虚假提升。

## 展示与导出

- 检索指标随 K 的折线图展示精准率、召回率和 MRR；命中率与 nDCG 保留在数值表。
- 回答质量柱状图展示忠实度、正确性、完整性及分子/分母、待审核和不适用数量。
- 同题实验对比展示检索指标差值和回答质量配对差值。
- CSV 与 Markdown 验收报告导出使用同一套计算口径。

## 边界

小样本均值不推断生产准确率或统计显著性。原文包含检查不是语义事实核验，
人工通过也不等于完整业务验收。需要业务签收时，应使用已核验、冻结的案例集并保留原始审核记录。
