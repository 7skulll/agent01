# 同页 RAG 评测第一版

更新：2026-10-19。入口：检索调试 → RAG 评测，沿用 `/retrieval`，未增加独立页面。

## 操作

1. 选择当前知识库，切换到 RAG 评测。
2. 选择“仅检索”或“完整 RAG”、全文/向量/混合模式和指标 K。
3. 输入 1–20 个问题。可只观察，也可标注“资料中有答案”并勾选完整的相关文件集合，或标注“应资料不足”。
4. 开始评测。仅检索不调用聊天模型；完整 RAG 复用真实任务、上下文和回答协议。
5. 查看指标卡片、K 曲线、逐题结果、耗时、实际查询、上下文预算、证据流转及最终引用。
6. 运行结束后保存人工答案评价。可载入历史配置重跑，或导出结果 JSON/CSV、导入/导出案例 JSON。

只勾选“检索范围”不会成为相关性标签；“相关文件”才是人工 qrels。
未标注题不生成检索质量分数。应拒答题也不进入正相关检索指标的分母。
实际 Token 缺失时显示“—”；已有 Token 用量按实际供应商返回值展示，不把估算混为实际量。

## 指标口径

第一版采用二值、文件级相关性。按真实最终检索结果的顺序取首次出现的 file_id，去重后评估。
同文件的多个切片不重复获得文件命中收益。原切片和排名仍在证据表中展示。

设前 K 个去重文件中有 H 个相关文件，人工标注相关文件总数为 R：

| 指标 | 定义 |
|---|---|
| Precision@K（精准率） | H/K，未返回的位置按不相关计 |
| Recall@K（召回率） | H/R |
| Hit@K（命中率） | 单题至少命中一个相关文件为 1，否则为 0；批量取均值 |
| MRR@K | 首个相关文件排名的倒数；前 K 无相关文件为 0 |
| nDCG@K | 二值相关性 DCG，位置折扣 1/log2(rank+1)，除以理想 DCG |

总体为有答案标注题的宏平均。已执行失败的标注题计零，同时显示失败题数；取消及未执行题排除。
图表固定显示 K=1/3/5/10/20，并提供可展开数值表，缺少有效标注时显示“未标注”。

例如只有一个相关文件且排第 1，Precision@5=20%，Recall@5=100%，并不表示回答准确率只有 20%。
当每题仅标一个相关文件时，Recall@K 和 Hit@K 数值相同。MRR/nDCG 是 0–1 归一化分数，页面用百分比刻度展示。

**边界：** 标注集合按穷尽相关集合解释，未标注文件按不相关处理。标注不完整会使精准率失真。
仅检索最多返回 20 个切片，再按文件去重；完整 RAG 使用服务端 retrieval_answer_candidates 配置。
因此曲线刻画当前实际输出链路，K 超过实际返回文件数时补空位；不代表全语料的理论召回能力。
K 是评估截断值，不修改问答候选数量、Rerank 开关或上下文预算。

## 检索、证据与回答分开评估

- 证据表显示同一检索流程去重后的初排、重排后顺序、是否进入上下文和是否被实际引用。
- 完整 RAG 的候选、组装资料和答案来自同一 run；不会为展示另发一次搜索。
- 规划查询、阶段耗时、组装诊断与 token_usage 直接取本次任务的快照/事件。
- “进上下文”按主块及 evidence_chunks 判断；没有进入或没有引用不自动说明不相关。
- 应拒答题中 completed + insufficient_evidence 的题数单列；有答案题中的资料不足单列为误拒答观察。
  这两个分母只覆盖成功完成的对应已标注 RAG 题，服务失败另外计数。
- 引用编号合法不等于语义事实受支持，人工评价采用 pending / pass / partial / fail，备注可记录事实缺失或无依据结论。
- 人工评价不会反向改写检索 qrels 和指标，审核要点只是人读提示，不做关键词匹配式自动打分。

## 执行、持久化与压力限制

- 单 worker 下仅运行一批，逐题执行，每批最多 20 题。POST 支持 UUID 幂等键；改变请求需更换键。
- 结果、案例、标注、逐题状态、人工审核和脱敏配置保存 PostgreSQL，刷新后可读取。
- 评测产生的会话标记 purpose=evaluation，不混入普通聊天列表。
- 保存文件哈希、切片版本、向量/全文版本、配置、端点哈希和应用源码指纹。
- 每题前后检查资料与配置快照；发生变化则标记失败/停止后续执行，避免悄悄混用实验条件。
- 停止会取消当前任务，保留完成题。创建任务阶段也受取消保护，防止留下不可见活动任务。
- 正常关闭保存为 stopped；意外重启遗留 running 记录标为 interrupted，并取消其遗留活动任务，不自动再次调用模型。
- 默认只在评测请求中采集较完整候选，普通搜索不新增候选正文快照。
- 没有引入基准框架、模型训练、自动下载或多任务并行；现有服务超时与模型调用预算继续生效。
- 当前历史列表保留最近 30 条入口；完整记录仍在数据库，当前选择的记录可直接读取。

迁移 `009_evaluations.sql` 启动自动执行，既有文件无需重建索引。

## API

前缀 `/api/v1/evaluations`。

| 方法与路径 | 用途 |
|---|---|
| POST 空路径 | 创建 1–20 题串行评测（202） |
| GET 空路径 | 最近 30 条评测摘要 |
| GET /{evaluation_id} | 结果、曲线、快照及审核 |
| POST /{evaluation_id}/stop | 停止，保留完成结果 |
| PATCH /{evaluation_id}/reviews/{index} | 结束后保存逐题人工审核，index 从 0 起 |
| GET /{evaluation_id}/export | 下载完整 JSON；CSV 在浏览器按当前结果生成，转义公式型单元格 |

案例 JSON 示例（导入的 ID 必须来自当前知识库）：

```json
[
  {"query":"年假多少天？","expected":"answerable","relevant_file_ids":["当前库文件ID"],"required_facts":"天数、适用条件和审批人"},
  {"query":"未记录的奖金是多少？","expected":"unanswerable","relevant_file_ids":[],"required_facts":"应说明资料不足"}
]
```

## 借鉴的基准及适配

- [BEIR 官方实现](https://github.com/beir-cellar/beir/blob/main/beir/retrieval/evaluation.py)：借鉴 corpus/query/qrels 分离与 IR 排名评估；这里选择二值文件级 qrels 和本地小样本，不声称是官方 BEIR 分数。
- [MTEB 官方项目](https://github.com/embeddings-benchmark/mteb)：借鉴任务、配置、数据集版本与结果可追溯的组织方式，第一版只覆盖现有文本检索和 RAG。
- [RAGBench 原论文](https://arxiv.org/abs/2407.11005)：借鉴检索相关性和回答质量分别评估的思想。第一版保留人工答案审核，不把文件命中率称为 faithfulness。
- [KILT 官方数据格式](https://github.com/facebookresearch/KILT#kilt-data-format)：借鉴答案与 provenance 一起保存。当前保存文件与实际证据快照，稳定原文区间和完整证据组放在第二版。

这些是方法参考，不是对官方数据集/评分流程的完整复现，也不与公开排行榜直接比较。

## 验证

后端纯单测包含去重、固定 K 分母、MRR/nDCG 手算、失败与无答案分母、标签一致性。
数据库测试包含同一真实任务链路、一次检索、记录隔离、幂等、标注范围、停止、取消创建竞态、快照变化与重启恢复。
浏览器测试包含同页切换、标注指标、无标注状态、曲线、人工审核、下载、刷新及 1440/1024/390px 布局。

两题真实服务验证：`uv run python -m scripts.smoke_evaluations`。
该脚本只在测试库隔离 schema 上传一份合成年假资料，验证回答、缺少事实拒答、真实重排和来源、指标及重启持久化，结束后清理。
后端全量 636 项、前端单测 7 项、浏览器回归 28 项及生产构建、Ruff 均通过。
报告：[evaluation-v1-smoke.json](../evals/results/evaluation-v1-smoke.json)。这两题只证明链路，不代表业务质量水平。
