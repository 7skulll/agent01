# RAG 评测第二版规划

更新：2026-10-19。第一版已经落地，见 [evaluation-v1.md](evaluation-v1.md)。
第二版继续使用“检索调试 → RAG 评测”，按收益逐项增加，保持单 worker 与小样本运行。

## 优先级 1：让标注和证据更可靠

1. 案例集保存为有名称、版本、业务标签的独立实体；标注 pending/positive/negative，明确完整与部分标注。
2. 以文件内容哈希 + 原文位置/文本片段标注必要证据，运行时映射切片，避免重切片后 chunk_id 全部失效。
3. 支持多事实、多个替代证据组，区分“命中文件”和“完整必要证据进入上下文”。
4. 部分标注情况下展示 judged coverage，限制精准率的解释；标注未完成的案例不得以负样本处理后发布业务结论。
5. 建立 30–50 个有代表性的业务案例；近似问题和同一场景同组划分，另建新的冻结测试集。

验收：同文件多个不相关片段不能因文件命中获得证据级满分；改变切片算法后仍能定位标注原文；缺失/失效标注明确显示。
参考 KILT 的 provenance 组织，适配本项目文档位置与快照，不加载 Wikipedia 全量知识源。

## 优先级 2：同题配对比较

- 在同页选择两个已保存实验，验证语料/案例/标注版本兼容后展示逐题胜/平/负、指标差值、耗时和 Token 差值。
- 首先比较已有的 keyword/vector/hybrid；随后增加评测专用 Rerank 开关和少量预算配置。
- 参数进入实验快照和幂等校验，不在实验中修改工作空间模型设置。
- 必要时重放同一候选或同一真实模型分数做局部对照，清楚标记缓存/重放，重放耗时不称为真实端到端耗时。
- 稳定基线后，对少量关键题重复 2–3 次观察波动；不默认全参数笛卡尔积测试。

验收：配置和数据不兼容时提示无法直接对比；不从 20 题直接声称显著提升或达到生产准确率目标。
参考 MTEB/BEIR 的数据版本与标准指标输出思想，不接入完整 benchmark runner。

## 优先级 3：回答质量与归因

- 将人工审核细化为必要事实覆盖、无依据事实、适用条件/例外、引用语义支持与应拒答原因。
- 显示解析缺证据 → 召回遗漏 → 重排丢失 → 组装丢失 → 生成错误的归因，支持多个原因与待确认。
- 接入可选 LLM 辅助审核，限制题数和调用预算，记录 judge 模型/提示词版本、判断理由和引用原文。
- 先用少量双人标注校准 judge；人工裁决保留优先权。自动分数与人工分数分别展示。
- 对应拒答/误拒答同时展示完成题表现与包含服务失败的整体运行表现，避免幸存者偏差。

参考 RAGBench 对检索与回答质量的拆分，第一步先在本项目资料和标签上验证审核尺度。
尚未实现独立事实 verifier，不把第一版人工总评改名为 faithfulness/adherence 指标。

## 按需求增加的运行能力

- 单批模型调用/Token 上限和执行前估算；供应商费用缺失时只展示用量，不虚构金额。
- 评测任务按案例重试与断点续跑，外部调用结果已知时复用；状态未知时显式确认后重跑。
- 历史分页、归档与评测数据删除，控制完整候选快照占用。
- 业务规模扩大后再考虑并行、任务队列、ANN 负载评测与监控集成。

## 当前不纳入

不训练 Embedding/Rerank，不运行完整 MTEB/BEIR/KILT/RAGBench，不自动下载大型语料，不要求 GPU 或新增数据库服务。
父子块/跨页解析优化仍属于 RAG 能力开发；评测先发现并量化问题，再决定是否实施。
