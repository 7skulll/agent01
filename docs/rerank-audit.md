## 方法与统计

- 默认使用固定种子的随机初排。随机身份只依赖语料、问题 ID 和 seed，排序不读相关性标签。
- 候选数量取当前 retrieval_rerank_candidates；语料不足时补固定合成干扰项，超出时按随机初排截取。
  不根据标签把正确文档塞进默认候选。原候选范围内不存在的标签计零分，并报告候选标签覆盖率。
- relevant-last 保留为显式压力场景，使用标签把相关文档置底；必须与默认随机初排分开解释。
- 每题只执行一次真实模型打分流程，再重放同一批分数比较原初排、配置权重、0.75 RRF 和纯模型排序。
  不为比较排序策略重复请求模型。配置权重为 0 时仍采集真实分数。
- 审计关闭相关性阈值，单独记录配置原阈值，保持排序对照；不修改 .env 或生产默认参数。
- 分别输出总体、数据集和题型指标：MRR、MRR@10、Recall@1/3/5、二值相关标签 nDCG@5。
  无答案题不进入上述排序均值，单列实际返回非空候选的题数。
- 标签引用不存在文档、重复文档/问题 ID、重复标签和缺失 relevant 时拒绝执行。
- 报告包含语料 SHA-256、随机种子和排序版本、候选列表、全量模型分数、每种策略排名与诊断。
  只有全部题目成功后才原子发布报告；失败不写入部分结果作为完整报告。

## 运行

```bash
uv run python -m scripts.audit_rerank --enable
uv run python -m scripts.audit_rerank --enable --dataset evals/bm25_holdout.json --output evals/results/rerank-holdout.json
uv run python -m scripts.audit_rerank --enable --order relevant-last --output evals/results/rerank-tail-stress.json
```

`--enable` 仅为本次审计启用服务，不修改配置。`--dataset` 可重复指定，未传时使用上表两套数据。
默认 seed=20261017，默认输出 [rerank-audit-v2.json](../evals/results/rerank-audit-v2.json)。
旧 rerank-v1-audit.json 与 rerank-optimized-audit.json 保留为历史小样本记录。

## 验证与结论边界

纯单测覆盖全量 36 题执行、每题一次打分、多策略分数复用、零权重、标签验证、
无相关候选时零分、无答案分母、候选顺序可复现及初排不使用标签。
纯单测全套 192 项通过，Ruff 与修改文件格式检查通过。
真实 BAAI/bge-reranker-v2-m3 全量 36 题已完成，候选限制 40，相关标签候选覆盖率 100%。

| 策略 | 有答案题 MRR | Recall@1 |
|---|---:|---:|
| 固定种子随机初排 | 0.1479 | 6.25% |
| 0.75 RRF | 0.6130 | 40.625% |
| 纯模型 / 本次配置权重 1.0 | 1.0000 | 100% |

4 道无答案题在阈值关闭时均返回候选。此处不以非空候选判作答成功，也未据此调整生产阈值。
精确配置、逐题排名和全量分数见第二版 JSON。

这仍是固定合成候选审计，既没有实际召回，也没有回答生成，不代表端到端 RAG 准确率。
无阈值时，无答案题也可能全部返回非空候选，不能把非空排序当作可回答或事实有据。
历史 holdout 在此次全量观察后不再是新的未触碰测试集；后续业务阈值校准仍需独立业务标注及验证集。
