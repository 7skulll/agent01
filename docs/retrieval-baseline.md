# 基础版检索与实测结果

日期：2026-10-15。

## 实现范围

单个原问题 → BM25 / 精确余弦并行召回 → 一次加权 RRF → 正文去重 → top_k。
不默认改写或扩展问题、不默认调用 Reranker、不默认补邻居、不使用词项覆盖率精排、
PageRank、SQL 或分层 RRF。旧的可选功能保留为显式扩展，本次评估全部关闭。

BM25 使用 SQLite FTS5。文档词项保留频率和顺序，查询词项才去重；中文继续采用双字词项，
不额外引入分词服务、字段权重、短语加权或同义词库。英文数字按原有规则切词。
词项版本已加入索引版本，因此旧索引需要显式调用 index 重建；原切片不因此重切。

候选池：向量 80，全文 60。RRF：`0.5/(60+vector_rank) + 0.5/(60+bm25_rank)`，
未命中通道不贡献分数。余弦阈值 0.2 仅用于向量候选预筛选，BM25 命中可独立进入融合。
这里没有把 BM25 和余弦原始分数相加，没有归一化为相关概率。

## 评估条件

- 真实 Embedding：`qwen3.7-text-embedding-flash`，返回 1024 维。
- 固定人工合成语料：24 篇文件，均为短文；20 个有答案问题与 2 个无答案观察问题。
- 问题包含精确编号、适用范围/版本、语义改述和事实定位；相关文件标签在运行前写入固定 fixture。
- 使用临时数据库与对象目录，不写入现有知识库，不调用回答模型。
- 同一组真实查询向量预计算并复用，保证向量与混合模式使用完全相同的向量。
- 只运行一次，未针对结果调权重、阈值或修改题目。测试规模小，不代表实际知识库质量。

## 结果

| 模式 | 首条命中率（Recall@1） | Recall@3 | Recall@5 | MRR@10 |
|---|---:|---:|---:|---:|
| BM25 | 90% | 95% | 95% | 0.925 |
| 向量 | 100% | 100% | 100% | 1.000 |
| BM25 + 向量 + RRF | 95% | 100% | 100% | 0.975 |

每个有答案问题有一个相关文件，因此本次 Recall@1 等于首条命中率。

查询向量化延迟：p50 146.98 ms，p95 233.74 ms（并发上限 2，统计单条调用耗时）。
以下为预计算查询向量之后的本地 API 搜索耗时，包含 HTTP 适配、SQLite 和融合；不代表端到端延迟：

| 模式 | 本地 p50 | 本地 p95 |
|---|---:|---:|
| BM25 | 1.33 ms | 2.15 ms |
| 向量 | 6.52 ms | 8.76 ms |
| 混合 | 6.96 ms | 7.23 ms |

只测一次，不能由这些小样本耗时判断哪种方案的生产 p95 更好。

## 失败案例与结论

- “登录口令想不起来了怎么办？”：BM25 首条误召回远程网络接入，未召回密码重置；
  向量将密码重置放在第一条。混合将远程网络接入排在第一、密码重置第二。
  本例说明：RRF 的通道共识可能放大错误的词面命中，混合不保证优于向量。
- “我刚来公司上班，去哪里拿门卡和电脑？”：BM25 首条为电脑维修，正确入职领取文档第二；
  向量与混合均首条正确。
- 两个无答案问题，三种模式均返回了候选。它们不计入 Recall/MRR。本次只测检索，
  没有评估生成答案或拒答；当前阈值不构成可靠的无答案检测。

这次结果支持保留简单基线，不支持“混合检索已经比向量更好”的结论。
下一步应加入用户真实文档与真实问题，继续使用同一评估方法，再决定是否需要改词项规则或融合权重。
暂不根据这 20 道题增加新的排序阶段。

## 复现

```bash
uv run python -m scripts.eval_retrieval
```

需配置 `.env` 中的 Embedding 模型、服务地址、密钥和单条 token 上限。
fixture：`evals/retrieval_baseline.json`；机器可读报告：`evals/results/baseline.json`。
报告保存数据集 SHA-256、参数、每题结果与分数。查询向量不落盘，每次复现都会重新调用真实服务。
离线回归：`uv run pytest -q`；覆盖真实 FTS5 词频排序、RRF 名次公式、默认关闭高级步骤与指标计算。
