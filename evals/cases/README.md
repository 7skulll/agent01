# 第三版案例草稿

`project-v3-draft.json` 从五份现有项目文档整理 30 道有原文出处的问题，开发 18 题、验收 12 题；相同场景不会跨集合。它是 **manifest**，尚无知识库文件 ID，不能直接放进页面“导入 JSON”。

所有案例为部分标注、review-pending、未冻结；不是用户实际业务数据，也不是通过业务验收的标准。

## 生成

在项目根目录运行：

```sh
uv run python -m scripts.prepare_evaluation_v3
```

仅在本地检查原文、计算哈希并写出草稿，不调用模型，不改数据库。

## 显式导入

先在工作台新建专用知识库，复制其 ID。下面命令会上传五份文档、绑定真实文件 ID/哈希、保存两个案例集草稿；不会自动运行评测。

```sh
uv run python -m scripts.prepare_evaluation_v3 --import-url http://127.0.0.1:8000 --kb-id 你的知识库ID
```

按需增加 `--index` 启动索引（可能调用 Embedding），也可在文件页手动构建。相同文件/草稿重试使用幂等上传键与不可变版本，避免相同内容反复创建。

在“检索调试 → RAG 评测 → 案例集与版本”载入，核对每个问题、相关文件集合及原文映射；补充真实业务问题和必要事实/限制条件。完整标注并人工核验后，另存冻结验收版本。业务例外、冲突、跨片段表格和应拒答案例仍需结合真实资料补充。

文档变化导致哈希或原文定位不一致时，重新生成并核验；不要只更换哈希后宣称已核验。运行和统计边界见 [第三版说明](../../docs/evaluation-v3.md)。
