## 口径与边界

- 只有配套新闻算正相关，**没有判定负相关**，所以 precision 不可计算；平台内该批案例
  `judgment_scope=partial`，Recall/nDCG 显示未评分是预期行为。上表按"已知正相关的召回"
  自行计算，不是完整 qrels 成绩，也不能称作召回率下界：补充相关性标注可能同时改变
  分子和分母，完整分数可能更高也可能更低。上述 R/nDCG 只针对官方配套文件集合。
- `H@k` 是"至少命中一篇"的比例；`R@k` 在 2/3 篇题上会小于 1。
- 匹配为文件级，不判断切片位置、也不判断答案是否被正确使用。
- 语料仅 220 篇、问题 42 条。二值题级命中差异 1 题 ≈ 2.4pp，宏平均召回的变化还取决于
  该题配套文档数，不统一等于 2.4pp；不做显著性推断。

## 现象

1. 所有配置在旧文件级范围内都至少命中一份配套新闻。这不能推出“全库召回不是瓶颈”，
   更不能证明事实证据完整。原先观察到的三文档题覆盖缺口包括：
   两处反复漏召的题都出现在 `questanswer_3docs`：
   - "哪些高校与地方政府合作……"（关键词/向量各漏 2 篇，混合漏 1 篇）
   - "宜黄县法院、白云区人民法院和某院……"（关键词/混合漏 1 篇）
   “高校”题已发现标注问题，不能直接归因召回；其他题需先补必要事实标注，再决定是否拆查询。
2. 混合（0.5/0.5）在旧文件级 R@5 低于向量，R@10 与向量相同。此结果尚不足以确立默认权重。
3. 重排在旧文件级口径中达到配套新闻全中，但前10片段并未全中；排除争议题后，
   向量与混合+重排都覆盖全部已知配套文档。重排 p50 从 219 ms 升到 871 ms（约4倍），
   当前没有证据证明这笔耗时改善了最终回答质量。
4. 关键词比向量更快（107 ms vs 218 ms），因向量路径每次都要调 Embedding 服务。

| 题 | 结果 |
|---|---|
| 荔湾区政府英文版上线日期与板块（1doc） | completed，回答与参考答案一致，服务端渲染 `[1]` |
| 成品油价格变化与走势（2docs） | 首次 `invalid_answer_schema`，**重试成功**且引用 `[1][2]` 正确 |
| 高校与地方政府合作（3docs） | completed，回答两所高校；上游参考答案第三项为湖北省政协，已隔离复核，暂不判漏答或错误拒答 |
| 湖北/十堰水利建设（3docs） | 失败 `internal_error`，日志为 `LengthFinishReasonError` |

首次执行是 2 题 completed、2 题 failed；另有成品油题一次独立重试 completed。
执行成功不等于事实正确，不将重试结果覆盖首次失败，也不从四题估算生产回答准确率。

两个执行失败应与检索质量分开分析：

- `invalid_answer_schema`：首次调用输出1002 token（reasoning 586），修复调用1323 token
  （reasoning 965）；两次均未通过结构化校验。仅靠这些数字不能归因为长度不足。
  新代码增加脱敏的 invalid_json/schema 诊断类别、JSON位置或schema错误类型，不记录原始答案。
- `LengthFinishReasonError`：`RAG_LLM_MAX_TOKENS=2048`，reasoning 已占 700–1000，
  长答案触顶。该异常被归为 `internal_error`（http 500、retryable），
  这是旧代码行为。新代码将 SDK 异常与消息 `finish_reason=length` 统一映射为
  `model_response_truncated`（502、不可原样恢复），不自动在相同上限下重试或消耗JSON修复。
  本次没有调高线上 Token 配置，4096只应作为后续对照实验，不作为已验证的修复。

## 建议

1. 先人工核验10–20题开发案例的事实、必要证据与适用范围，再扩大标注。
2. 以相同片段预算比较检索、重排、上下文证据覆盖及完整回答，不把文件数当事实数。
3. 继续记录首次调用与修复调用：token_usage 的 attempt_id 是任务内模型调用序号，
   is_repair/repair_attempt 区分协议修复；不是独立实验重试次数。SDK 截断但无可靠 usage 时
   记录 actual=null，不把未知用量当0。后续可对照输出预算，不自动提高默认上限。
4. `missing_fact` 已能表达资料不足；缺的是事实级覆盖判断，不能简单数实体或从金标倒推
   用户必须问了几个实体。也不因人工判full就声称自动拒答可靠。
5. 校准开发集后再讨论多查询和混合权重；预留18题维持未运行，不参与本次调参。
